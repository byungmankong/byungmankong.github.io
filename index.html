#project-detail-etl

프로젝트 상세: 데이터 수집·연동 자동화

웍스피어(잡코리아 담당) 재직 시, NICE 기업정보 데이터를 받아 잡코리아 데이터베이스에 삽입하는 과정을 SSIS로 구축·관리했습니다.

전체 흐름

점선 박스가 SSIS 패키지 범위입니다.

단계별 SSIS 구성

단계구성요소하는 일
Staging 적재Source → OLE DB Destination받은 데이터를 가공 없이 임시 테이블에 적재
정제·검증Data Conversion, Derived Column자료형 변환, 공백·NULL·중복 정리
기업 매칭Lookup기존 잡코리아 기업과 동일 기업 식별
분기Conditional Split신규는 Insert, 변경분은 Update로 분리
오류 처리Error Output실패한 행과 사유를 로그 테이블에 저장

패키지 실행 순서

Control Flow
1. SQL 실행   Staging 초기화
2. Data Flow  NICE 데이터 → Staging
3. SQL 실행   건수·품질 검증
4. Data Flow  Staging → 기업정보 (매칭·분기)
5. SQL 실행   처리 결과 로그 기록

운영 관점

  • 재실행 안전성: 매 실행 전 Staging을 비워 실패 후 다시 돌려도 중복 적재되지 않게 구성
  • 건수 대사: 수신 건수와 적재 건수를 비교해 누락 확인
  • 스케줄과 알림: SQL Server Agent 작업으로 실행하고 실패 시 알림
  • 오류 행 관리: 오류 행을 버리지 않고 사유와 함께 별도 보관
#project-detail-ha

프로젝트 상세: 고가용성·백업·업그레이드

잡코리아 SQL Server 환경에서 Always On 가용성 그룹으로 고가용성을 구성했습니다. 이전에는 MSSQL Replication·Clustering과 MySQL Replica로 HA를 구성한 경험도 있습니다.

구성도

구성요소

구성요소역할
WSFC 클러스터노드 상태 감시와 장애 조치 기반
가용성 그룹(AG)여러 DB를 묶어 복제본 간 동기화
리스너애플리케이션이 항상 현재 Primary로 접속
동기 커밋데이터 손실 없이 자동 장애 조치
비동기 커밋읽기 전용 조회·백업 분산, 원거리 복제

장애 조치 흐름

1. Primary 장애를 WSFC가 감지
2. 동기 Secondary가 Primary로 승격
3. 리스너가 새 Primary로 연결 전환
4. 애플리케이션이 재연결하여 서비스 지속
5. 복구된 기존 Primary는 Secondary로 재편입

선택 이유와 운영 관점

  • 선택 이유: 공유 스토리지 없이 복제본별 독립 스토리지로 구성할 수 있고, Secondary를 읽기·백업에 활용 가능
  • 모니터링: 동기화 상태와 로그 전송 지연을 지속 확인
  • 장애 조치 리허설: 실제 장애 전에 절체 테스트로 절차 검증
  • 패치·업그레이드: Secondary부터 순차 적용해 서비스 중단 최소화
